# Emaar Group CRM - نظام إدارة العملاء العقاري

## 🎯 نظرة عامة
نظام CRM متكامل لإدارة العملاء العقاري مع نظام صلاحيات متعدد المستويات وتوزيع الأرقام على فريق المبيعات.

## ✨ الميزات الرئيسية

### 🔐 نظام تسجيل الدخول
- **صفحتان منفصلتان**: دخول الإدارة ودخول السيلز
- **حساب المدير الافتراضي**: 
  - اسم المستخدم: `admin`
  - كلمة المرور: `admin123`

### 🪄 الدخول إلى حساب سيلز بضغطة واحدة (حساب جوا حساب)
المدير يقدر يدخل **داخل** حساب أي سيلز ليرى النظام بعينيه بالضبط — بدون أي اسم مستخدم أو كلمة مرور.

- **من أين تدخل؟** زر <kbd>الدخول إلى الحساب</kbd> (أيقونة 🔑 سماوية) موجود في ثلاث شاشات: **فريق العمل**، **إنشاء حسابات سيلز**، و**الإعدادات ← حسابات الفريق**.
- **ما تراه؟** نفس التبويبات ونفس البيانات التي يراها ذلك السيلز (بما فيها سجل حضوره وأرقامه) — مفيد لتشخيص مشكلة يقولها لك أحد السيلز أو للتأكد أن ما يراه سليم.
- **كيف ترجع؟** شريط برتقالي يظهر مُثبّتاً في أعلى الشاشة فيه اسم السيلز وزر **«الرجوع لحساب الإدارة»** — ضغطة واحدة بلا أي بيانات دخول. نفس الزر موجود أيضاً أعلى يمين الصفحة، وزر الخروج (⏏) بجانبه يعمل كخروج نهائي من النظام.
- **ملاحظات:** الدخول للحسابات الموقوفة أو لحسابات المديرين غير متاح، والجلسة تبقى محفوظة لو حدّثت الصفحة (محفوظة على جهازك وحده ولا تُزامَن مع بقية الأجهزة).

### ⏰ الحضور والانصراف — لمن؟
- **الحضور للسيلز فقط.** حساب الإدارة **لا يوجد له حضور ولا انصراف أصلاً**، ولا يظهر في تبويب «الحضور»، لأنه غير مطالب بالتسجيل اليومي.
- **أثناء دخول الإدارة إلى حساب سيلز** يختفي كارت الحضور والانصراف تماماً — الإدارة لا تسجّل حضوراً بدلاً من السيلز. (لو أردت متابعة حضور شخص: افتح تبويب **الحضور** من حسابك، وهناك كل حساب منفصلاً بتوقيته وموقعه على الخريطة.)

### 📱 الاستخدام على الهاتف (أندرويد وآيفون)
النظام مضبوط بالكامل للهاتف — لا حاجة إلى «ديسكتوب سايت» ولا تكبير أو تصغير يدوي.

- **الشريط العلوي** على الهاتف مضغوط ومصمم ليكون في سطر واحد (بلا اسم الشركة المكرر ولا الشارات المتراكمة)، والأزرار لمسية بحجم مناسب للإصبع.
- **القائمة الجانبية** تُفتح بزر ☰ من اليمين وتُغلق بالضغط خارجها أو باختيار أي تبويب.
- **تبويب المحادثات** يتحول على الهاتف إلى 👉 `قائمة السيلز` ثم `المحادثة` وحدها بزر رجوع (مثل تطبيقات الشات)، وليس قائمتين جنباً إلى جنب.
- **كل النوافذ** (إضافة عميل/عقار/تذكير/فيدباك، والتعديل، والإعدادات) تتمرر داخلياً على الشاشة الصغيرة وفيها زر ✅ إغلاق ظاهر — فلا تنحشر خلف الكيبورد.
- **إضافة إلى الشاشة الرئيسية:** من متصفح الهاتف ← القائمة ← «تثبيت التطبيق» أو «إضافة إلى الشاشة الرئيسية»، فتحصل على أيقونة باسم **Emaar CRM** تفتح **ملء الشاشة بدون شريط المتصفح** (لأن الموقع فيه `manifest` وأيقونات ١٩٢/٥١٢ ومظهر `standalone`).
- **العمل بلا بيانات:** ستفضل جلسة الدخول محفوظة بعد إغلاق المتصفح، والبيانات تصل من السيرفر خلال ثوانٍ عند الفتح.

> لا تُفعّل «Desktop site» في المتصفح: النظام يتكيّف تلقائياً مع أي مقاس، والنسخة المكتبية ستظهر ضيقة على الهاتف.

### 💬 الشات الداخلي (الإدارة ↔ كل سيلز)
محادثة خاصة بين الإدارة وكل حساب سيلز، بدون أي تطبيق خارجي.

- **الإدارة**: تبويب **المحادثات** — قائمة بكل السيلز مع آخر رسالة ووقتها، وبنقطة حمراء بعدد الرسائل الجديدة لكل شخص، وبحث بالاسم. اضغط أي اسم لتفتح محادثته.
- **السيلز**: تبويب **المحادثة** — نافذة واحدة مع الإدارة، والإدارة ترد عليه هو وحده.
- **إشعار فوري**: أيقونة 💬 في الشريط العلوي تحمل عدد الرسائل غير المقروءة، وعند وصول رسالة جديدة يحدث صوت + اهتزاز + إشعار على الشاشة.
- **علامة القراءة**: تظهر «أُرسلت ✓» ثم «تم القراءة ✓✓» بعد أن يفتح الطرف الآخر المحادثة.
- **تصل على كل الأجهزة** خلال ثوانٍ (نفس محرك المزامنة)، وكل سيلز لا يرى إلا محادثته هو.
- **أثناء دخول الإدارة إلى حساب سيلز**: يستطيع قراءة محادثته، لكن **الإرسال معطّل** ورسائل السيلز **لا تُعلَّم كمقروءة** حتى لا تفوت عليه.

### 👥 نظام الأدوار

#### الإدارة (Admin/Supervisor)
تبويبات الإدارة:
1. **فريق العمل** - عرض السيلز والمشرفين مع إمكانية عرض الفيدباك اليومي لكل شخص
2. **الفيدباك اليومي** - عرض إحصائيات وفيدباك كل سيلز
3. **توزيع الأرقام** - إضافة أرقام جديدة وتوزيعها على السيلز
4. **إنشاء حسابات سيلز** - إنشاء حسابات جديدة للسيلز
5. **الإعدادات** - تصدير البيانات وإعدادات النظام

#### السيلز (Sales)
تبويبات السيلز:
1. **الرئيسية** - لوحة التحكم مع الإحصائيات
2. **العملاء** - إدارة العملاء مع إمكانية إضافة أرقام متعددة
3. **المراحل** - عرض العملاء حسب المرحلة (Pipeline)
4. **العقارات** - إدارة العقارات مع بحث ذكي
5. **التذكيرات** - إدارة تذكيرات الاتصال
6. **الفيدباك** - تسجيل الفيدباك اليومي
7. **أرقام جديدة** - عرض الأرقام الموزعة من الإدارة
8. **التقارير** - إحصائيات وتقارير الأداء

### 📞 نظام توزيع الأرقام

#### للإدارة:
- إضافة أرقام جديدة من تبويب "توزيع الأرقام"
- تحديد السيلز الذي سينزل له الرقم
- إضافة وصف/ملاحظات للرقم
- عرض حالة كل رقم (جديد / تم العرض / تم التواصل / مغلق)

#### للسيلز:
- عرض الأرقام المخصصة له فقط في تبويب "أرقام جديدة"
- حالة الرقم:
  - **رقم جديد**: لم يشاهده السيلز بعد
  - **تم العرض**: شاهد السيلز الرقم
  - **تم التواصل**: تم الاتصال بالعميل
  - **مغلق**: تم إغلاق الصفقة
- زر "تم العرض" لتأكيد مشاهدة الرقم
- زر "اتصال" للاتصال المباشر

### 🔍 البحث الذكي في العقارات

يدعم البحث عن العقارات بـ:
- **الأرقام**: `1000000` أو `1,000,000` أو `10000`
- **الكلمات العربية**: `مليون`, `مليونين`, `ألف`, `نصف مليون`, `عشر آلاف`, `مية وخمسين ألف`, `مليون وميتين ألف`
- **الغرف بأي صيغة**: `غرفتين`, `أوضتين`, `3 غرف`, `تلات غرف`, `غرفة واحدة`
- **النص**: اسم العقار، النوع، الموقع، رقم العميل أو رقمه الإضافي — والكلمات بأي ترتيب
- **التشطيب والتسليم**: متشطبة، نصف تشطيب، طوب، تسليم فوري…

### 🧠 البحث باحتياجات العميل (تبويب العقارات)

زر **«🧠 احتياجات العميل»** يفتح خانة تكتب فيها كلام العميل بحرّية، والنظام **يفهم النوع والمبلغ والمساحة والغرف والمنطقة والتشطيب والتسليم** ويرشّح العقارات مرتّبة بالأقرب.

**مثال حقيقي**: `العميل محتاج شقة غرفتين في التجمع الخامس بمساحة مية وعشرين متر بعشر آلاف جنيه`

يفهم منه:
- **النوع**: شقة | **السعر**: 10,000 → 15,000 ج.م (يوسّع ١.٥× حول المبلغ) | **المساحة**: 100 → 150 م | **الغرف**: 2 | **المنطقة**: تجمع
- الأرقام تُفهم **بالأرقام (٢، 2، 1,500,000) أو بالحروف (عشر آلاف، مية وخمسين ألف، مليون وميتين ألف، نص مليون)** — ويُفهم (من … إلى …)، و(لحد / حتى / ميزانية)، و(فوق / أكثر من).
- الغرف تُفهم بكل الصيغ: **غرفتين، أوضتين، ٣ غرف، تلات غرف، غرفة واحدة، غرفة نوم**.
- حدود البحث **قابلة للتعديل** بعد الفهم، وتحتاج ضغطة «طبّق الفلتر» لتُثبَّت على القائمة.
- النتائج على مجموعتين: **مطابقة** و**قريبة (تحتاج مراجعة)**، مع سبب واضح لكل عقار، وخط «أمثلة لما استبعدناه» وأسبابه.

### 💰 نظام الأسعار
- **فواصل تلقائية**: الأسعار تظهر بفواصل (مثل: `1,500,000`)
- **دعم الكلمات العربية**: يمكن كتابة السعر بالكلمات (مليون، ألف، إلخ)
- **تحويل تلقائي**: يتم تحويل الكلمات إلى أرقام للحفظ والبحث

### 📊 الفيدباك اليومي

#### للإدارة:
- عرض كل سيلز في بطاقة مع إحصائيات:
  - عدد فيدباك اليوم
  - عدد مكالمات اليوم
  - إجمالي الفيدباك
  - إجمالي المكالمات
- الضغط على أي سيلز يعرض كل الفيدباك اليومي الخاص به

#### للسيلز:
- تسجيل فيدباك يومي لكل عميل
- حالة الاتصال:
  - تم الاتصال
  - لا رد
  - مشغول
  - لم يتصل
- مدة المكالمة
- الإجراء التالي
- ملاحظات

#### 🎯 شريط الفيدباك (٩ حالات بجوار كل اسم عميل)

على كل عميل في تبويب **«العملاء»** (وفي الجدول أيضاً) يوجد **شريط فيدباك** فيه ٩ حالات — كل حالة تلون الشريط عند اختيارها:

| الحالة | المعنى | المرحلة تلقائياً |
| --- | --- | --- |
| `follow up` | متابعة | تم التواصل |
| `meeting` | موعد معاينة / اجتماع | موعد معاينة |
| `following after meeting` | متابعة بعد الاجتماع | موعد معاينة |
| `reschedule meeting` | إعادة جدولة الاجتماع | موعد معاينة |
| `cancellation` | إلغاء | ضائع |
| `no answer` | لا يوجد رد | تم التواصل |
| `done deal` | تم البيع | تم البيع |
| `reservation` | حجز | تفاوض |
| `fresh stage` | مرحلة جديدة | جديد |

- **الفيدباك = حالة + كومنت معاً**: زر الحفظ يظل معطّلاً حتى تختار حالة **وتكتب كومنت** — فلا يوجد كومنت بلا حالة ولا حالة بلا كومنت.
- الكومنت يُسجّل في **خط العميل الزمني** فيظهر في خانة الكومنتات (الفيدباك) وفي **تبويب «الفيدباك اليومي»** فوراً، ومعه شريحة الحالة الملوّنة.
- **`no answer` تكتب الكومنت من نفسها**: بمجرد اختيارها (في الشريط أو في نافذة المكالمة) يُكتب في الكومنتات `No answer` تلقائياً — ويمكن للمندوب تعديله.
- اختيار الحالة يحرّك **مرحلة العميل تلقائياً** (بلا ضغطة إضافية) فيبقى تبويب «المراحل» صادقاً.

### 🚀 النشر على الاستضافة (كل تعديل ينزل معه)

الاستضافة تشتغل من الفرع `master` مباشرة: **أي تعديل يجب أن يُنشر، لا يبقى على جهاز المكتب.**

```bash
npm test          # لا ترفع قبل أن تنجح كل الاختبارات
npm run build     # تأكيد أن البناء يمشي
node scripts/...  # أي تحقّق إضافي مطلوب
```

ثم:

```bash
git add <الملفات المعدّلة> && git commit -m "..." && git push origin master
```

- الدفع إلى `master` يشغّل بناءً جديداً على Vercel تلقائياً (المشروع `emmaar-group-crm`).
- **تحقّق أن النشر نزل فعلاً**: قارن بصمة الـ bundle المنشور ببناءك المحلي —
  `curl -s https://emmaar-group-crm.vercel.app/ | grep -oE 'index-[A-Za-z0-9_-]+\.(js|css)'`
  ويجب أن تطابق اسم الملف في `dist/assets/` (البناء على Vercel يستغرق أقل من دقيقتين).
- متغيّرات البيئة (قاعدة البيانات + `AUTH_SECRET`) مضبوطة على Vercel ولا تُرفع مع الكود أبداً.

### 🔔 الإشعارات خارج الموقع + رنّة التذكيرات

**الإشعارات الحقيقية (الموقع مقفول):** من زر الجرس في الشريط العلوي ← «تفعيل الإشعارات» مرة واحدة على كل جهاز. بعدها:
- **رسائل الشات** تصلك حتى لو الموقع مقفول (من السيرفر ← منصة إشعارات المتصفح)، وتتكرر كل ٢٠ ثانية حتى تفتح الموقع.
- **التذكيرات** تصلك أيضاً خارج الموقع مع أزرار (فتح / تأجيل ٥ دقائق).
- على أندرويد: من قائمة المتصفح «إضافة إلى الشاشة الرئيسية» ليعمل كتطبيق. وعلى آيفون يتطلب الأمر نفسه (iOS 16.4+).

**رنّة التذكيرات داخل الموقع:** عند حلول وقت التذكير يظهر إشعار مكانه المعتاد أعلى الصفحة (بنفس شكله المألوف) **وتُرنّ صوت الجرس**:
- الرنة تتوقف بزر **🔕 إسكات** من الإشعار نفسه، أو بإسكات الجهاز، أو بزر **✅** لإتمام التذكير.
- مدة الرنة ومستوى الصوت والتأجيل (دقيقة / ٥ / ١٠ / ١٥ دقيقة) من نافذة الإشعارات، وفيها زر **تجربة الصوت**.

### 📊 تقرير الحضور الشهري (للإدارة)

داخل تبويب **الحضور والانصراف** — بطاقة **«التقرير الشهري للحضور»**: جدول لكل مندوب في الشهر المختار.

- **الأعمدة**: أيام الحضور، أيام التأخير، إجمالي دقائق التأخير، أيام بلا انصراف، أيام انصراف مبكر، إجمالي دقائق الانصراف المبكر، أيام بلا تسجيل، ساعات العمل، متوسط اليوم، أبكر حضور، آخر انصراف — مع **صف إجمالي** للجميع.
- **مواعيد الدوام**: الحضور افتراضيًا **10:00**، و**سماحية 30 دقيقة** (التأخير يُحسب بعد 10:30)، والانصراف **18:00**. كلها قابلة للضبط، و**يوم الراحة** (الجمعة / السبت / لا يوجد) يُستثنى من أيام العمل المتوقعة.
- **«تنزيل التقرير (Excel .xlsx)»**: ملف Excel حقيقي (xlsx) بترميز UTF-8 واتجاه RTL، يفتح مباشرة في Excel وGoogle Sheets وWPS وONLYOFFICE — بدون أخطاء فتح ملفات CSV.

### 📞 واتساب بضغطة واحدة

في كارت كل عميل (وملخّص العميل، وفي تفاصيل العقار لأرقام العملاء) — زر **واتساب** أخضر:
- يفتح نافذة فيها أرقام العميل (رقم أساسي + أرقام إضافية) لتختار أيّها.
- **بلا أي رسالة مكتوبة مسبقاً**: يُفتح واتساب على الرقم مباشرة والمندوب يكتب رسالته بنفسه داخل المحادثة.
- الرقم يُحوَّل تلقائياً للصيغة الدولية (`01012345678` ← `201012345678`) ويفتح `wa.me` مباشرة بلا مكتبات أو حسابات.

### 📱 أرقام إضافية

كل **عميل** يقبل عدة أرقام (الرقم الأساسي + أرقام إضافية)، وكل **عقار** يقبل **رقمين**: رقم العميل و**رقم تانٍ اختياري** (رقم المالك أو رقم إضافي) — ويظهر كلاهما في التفاصيل وفي البحث، وكلٌّ له زر اتصال وواتساب.

### 🖼 صور الوحدات + الخريطة

في نموذج **إضافة عقار**:
- **صور الوحدة** (حتى ٦ صور) تُختار من الكاميرا أو الجهاز، و**تُضغط داخل المتصفح** (أقصى طول ١١٠٠ بكسل، جودة ٧٢٪) فتصبح عشرات الكيلوبايتات فقط ثم تُحفظ داخل بيانات الشركة نفسها — **بلا أي خدمة تخزين خارجية**.
- **«📍 التقط موقع الوحدة»** يقرأ إحداثيات الجهاز ويحفظها مع العقار (ويعمل على الهاتف عبر رابط الشبكة لأن الموقع HTTPS).
- تظهر **صورة الغلاف** على كارت العقار مع شارات «🖼 عدد الصور» و«🗺 على الخريطة»، وفي التفاصيل **معرض صور** كامل + **خريطة جوجل** مركّبة + زر «افتح في خرائط جوجل».

### 🧭 الخط الزمني لكل عميل

كل حدث على العميل يُسجَّل **تلقائياً** داخل سجله ويظهر في كارت العميل بالوقت واسم من قام بالحدث:
- إضافة العميل (🆕) • تغيير المرحلة (🎯) • إنشاء تذكير (⏰) • تنفيذ تذكير • فيدباك (📞) • فتح اتصال (☎️) • إرسال واتساب (💬) • وصول ليد من الرابط العام (🔗).

السجل محفوظ **داخل سجل العميل نفسه** (آخر ٦٠ حدثاً)، فيسافر مع المزامنة لكل الأجهزة بلا أي جدول إضافي.

### 📈 لوحة التحليلات (للإدارة)

تبويب **«التحليلات»** في حساب الإدارة:
- خمس بطاقات مباشرة: إجمالي العملاء • صفقات مغلقة • نسبة التحويل • تذكيرات متأخرة • العقارات.
- **قمع المراحل**: عدد العملاء ونسبتهم في كل مرحلة (مقارنة بصرية بين المراحل).
- **مصادر الليدز**: كل مصدر (كامبين / فيسبوك / الرابط العام…) بعدد العملاء.
- **أداء فريق المبيعات**: جدول لكل سيلز (العملاء، المغلقة، الضائعة، نسبة التحويل، الفيدباك، التذكيرات المتأخرة، آخر نشاط).

### 🔗 الرابط العام للعقار — يجلب ليدز من خارج النظام

في تفاصيل أي عقار زر **📋 نسخ الرابط** و**💬 مشاركة واتساب**:
- الرابط (`/p/<رقم العقار>`) يُفتح لأي عميل **بلا تسجيل دخول** ويعرض الصور والسعر والمساحة والموقع على الخريطة + **فورم لتسجيل الرقم**.
- بمجرد الإرسال يدخل العميل فوراً إلى قاعدة البيانات **معزولاً على صاحب العقار** مع حقل `source` = «الرابط العام» و**حدث في خطه الزمنى**، ثم يوزَّع/يُتابع من النظام كأي ليد.
- **منع التكرار**: لو الرقم موجود بالفعل فلا يتكرر العميل — يُضاف حدث «سجل اهتمامه من الرابط العام» على سجله.

### ♻️ المتابعة التلقائية

بعد أي تغيير في مرحلة العميل يُنشئ النظام **تذكير متابعة بعد ٢٤ ساعة (١٠ صباحاً)** لصاحب العميل من تلقاء نفسه، بملاحظة واضحة وشارة «تلقائي» في تبويب التذكيرات — فلا يبقى عميل بلا متابعة، ولا يتكرر التذكير لو يوجد تذكير قائم لنفس العميل.

## 🎨 المظهر (ليلي / نهاري)

وضعان فقط، يختارهما كل موظف من زر **ليلي/نهاري** في القائمة الجانبية أو أعلى الشاشة، أو من **الإعدادات ← مظهر الموقع**.

- **الوضع الليلي:** رمادي مزرق غامق (`#0b1220`) وبطاقات `#111827` وحدود بيضاء شفافة ٨٪، مع **لون أساسي واحد** أزرق (`#3b82f6`) — بلا توهجات بنفسجية.
- **الوضع النهاري:** خلفية `#f7f9fc` وبطاقات بيضاء بحدود رمادية رقيقة، وأزرق أغمق (`#2563eb`).
- **الخطوط:** عناوين بتدرج هادئ درجة واحدة (كحلي ← أزرق) بدل التدرجات الصارخة، وظلال ناعمة واقعية بدل التوهج.
- **الأيقونات والشارات تتبع الثيم:** كل الألوان الزخرفية في الموقع مربوطة بمتغيرات الثيم، فتتغير درجتها تلقائياً مع تبديل الوضع أو تغيير هوية الموقع من مكان واحد.
- **ألوان الحالة لا تتبع الثيم** وتبقى بمعناها ثابتاً (أخضر/كهرماني/أحمر).
- **التغيير فوري ويُحفظ على جهاز هذا الموظف وحده**، ولا يغيّر شاشة غيره؛ وكل الألوان والحدود والبطاقات تتبعه (ولون شريط النظام في الهاتف أيضاً).
- **ألوان الحالة لا تتغير أبداً بين الوضعين** (أخضر = حاضر/نجاح، كهرماني = انصراف/تحذير، أحمر = حذف) حتى يبقى المعنى واضحاً بنظرة.

## 🔔 مركز الإشعارات (مقسَّم وشغّال)

زر 🔔 في الشريط العلوي يفتح مركزاً مقسَّماً على تبويبات، وفوقه **عدّاد أحمر** بما لم تره بعد (يختفي التبويب الذي تفتحه من العدّاد):

| التبويب | لمين | بيوصله إيه |
|---|---|---|
| **التذكيرات** | الجميع | كل تذكير غير مكتمل، والمستحق الآن يتلوّن أحمر |
| **أرقام جديدة** | السيلز | الأرقام التي نزلت له من الكامبين/المصادر ولم يكلمها |
| **الرسائل** | الجميع | رسائل الشات الواردة له |
| **اتصالات الفريق** | الإدارة | كل مكالمة سجّلها أي سيلز: تم الرد / لم يرد + الكومنت + موعد الاتصال القادم |

وفي أسفله زر **⚙️ إعدادات الإشعارات والمنبه** (نفس الإعدادات السابقة) وزر لفتح القسم المختار مباشرة.

## ☎️ تسجيل المكالمات (من السيلز إلى الإدارة)

من كارت أي عميل (أو من تفاصيله) ← زر **اتصال**:

1. **اتصل الآن** يفتح الاتصال الفعلي بالرقم من الجهاز.
2. تختار النتيجة: **تم الرد ✅** أو **لم يرد ❌**.
3. يظهر حقل **كومنت/فيدباك** يُرسل للإدارة، وتحته **موعد الاتصال القادم** بأزرار سريعة (بعد ساعة / ٣ ساعات / بكرة / أسبوع) أو بتحديد الوقت بنفسك.
4. بالحفظ: يُسجَّل **سجل مكالمة مشترك** تراه الإدارة فوراً في «اتصالات الفريق»، ويُضاف حدثان في **الخط الزمني للعميل**، ويُنشأ **تذكير تلقائي** بموعد الاتصال القادم.

> السجل يُزامَن في `crm_call_logs` مثل باقي البيانات — فما يسجّله أي سيلز على هاتفه يظهر عند المدير في ثوانٍ.

## 🧱 قائمة «العملاء» — وضعان للعرض

زرّان في أعلى التبويب يبدّلان الشكل (ويُحفظ اختيارك على جهازك):

1. **الشريط العادي**: سطر لكل عميل — الاسم، الرقم، شريحة الحالة الملوّنة، المصدر، عدد التعليقات، وأزرار الاتصال/واتساب.
2. **كل الأرقام فوق بعضها**: بطاقة لكل عميل بجانبها التفاصيل الكاملة (العقار، الميزانية، القسط، مصدر الليد مثل `Facebook Campaign`، آخر تعليق).

**شرائح الحالة بألوان منظمة:** 🆕 جديد (أزرق) • 📞 تم التواصل (بنفسجي) • 📅 موعد معاينة (سماوي) • 💬 تفاوض (كهرماني) • ✅ تم البيع (أخضر) • ❌ ضائع (أحمر).

**شريط الفيدباك** بجوار كل اسم عميل (في الكروت وفي الجدول): ٩ حالات ملوّنة، والحالة المختارة تضيء بلونها مع آخر كومنت مكتوب — التفاصيل في قسم «شريط الفيدباك» أعلاه.

**أرقام الكامبين** تظهر الآن **داخل تبويب العملاء مباشرة** (لا يوجد تبويب منفصل) ومعها زر «أضف لعملائي» لتحويل الرقم لعميل بضغطة واحدة.

## 🔒 الأمان والتحصين

- **البيانات لا تُقدَّم إلا لحساب مسجَّل دخوله — على السيرفر.** تسجيل الدخول يتحقق من كلمة المرور في السيرفر (`/api/auth`) ويُصدر **كوكي جلسة HttpOnly موقّعاً بـ HMAC-SHA256** بمفتاح `AUTH_SECRET` السري السيرفري. النتيجة العملية: من يعرف رابط الموقع يحصل على شاشة دخول فقط، و`/api/store` ترد **٤٠١** لأي طلب بلا جلسة صحيحة — لا قراءة ولا كتابة ولا حتى معرفة رقم الإصدار. والكوكي لا يستطيع أي JavaScript قراءته، فلا يمكن سرقته بـ XSS.
- **كلمات المرور يديرها النظام — والإدارة وحدها.** شاشة «تعديل الحساب» تعرض للـ CEO كلمة مرور أي سيلز وتسمح بتعيين واحدة جديدة (تعمل فور الحفظ)، وأي محاولة تغيير من حساب آخر — أو طلب مُصنَّع من DevTools — **تُهمل على السيرفر تماماً** (`preserveUserPasswords`). البديل لمن يحب سطر الأوامر: `node scripts/set-password.mjs`.
- **الدخول كلّه من السيرفر**: لا يوجد في المتصفح أي تحقق أو مقارنة لكلمات المرور، ورقم إصدار الجلسة لا يغادر السيرفر أبداً. كلمات المرور المشفّرة القديمة (SHA-256 + ملح) ما زالت تعمل، والجديدة تُحفظ نصاً كي تراها الإدارة، ولا تُمسح أبداً من كتابة تاركة كلمة (فلا يقفل أحد حسابه بالخطأ).
- **الخروج يُبطل كل جلسات الحساب فوراً** (وكذلك تغيير كلمة المرور) عبر رقم إصدار جلسات لا يملكه المتصفح — فحتى نسخة مسروقة من الكوكي تموت بعد الخروج.
- **تخمين كلمة المرور محدود**: ١٢ محاولة فقط لكل IP واسم مستخدم خلال ١٠ دقائق (٤٢٩ بعدها)، وبلا كشف إن كان الاسم موجوداً أصلاً.
- **إعدادات سحب الأرقام (توكن فيسبوك) للإدارة فقط** ولمن كلمة مروره قوية.
- **فصل كامل بين البيانات**: السيلز يرى عمله، قائد الفريق فريقه، والـ CEO الكل — والتحقق من الصلاحيات في كل عملية.
- **ضد الإغراق (Rate limiting)**: حد للطلبات لكل IP على واجهة البيانات، وحد أشدّ على الرابط العام المفتوح (٣٠ طلباً / ١٠ دقائق).
- **تحقق من المدخلات**: حد أقصى لعدد السجلات، وحد لحجم الطلب (24 ميجا يكفي لصور العقارات)، وتعقيم كل النصوص في الصفحة العامة (منع XSS).
- **حماية الحضور من التلاعب**: كشف **Fake GPS** (دقة مستحيلة أقل من متر، إحداثيات ثابتة بالضبط بين الأيام) و**VPN** (تعارض توقيت الجهاز مع الموقع) و**التنقّل المستحيل** (سرعة أعلى من أي وسيلة نقل) — والحضور يُسجَّل مع علامة حمراء **«مشكوك في الموقع»** في صفحة الإدارة مع ذكر الأسباب.
- **إرشاد تفعيل الـ GPS**: لو الموقع مقفول أو الصلاحية مرفوضة، يظهر للمندوب نافذة بالخطوات الدقيقة (إعدادات الهاتف ← الموقع ← دقة عالية ← سماح للمتصفح) وزر «حاول مرة أخرى».

## 💾 تخزين البيانات (سيرفر محلي)

البيانات كلها تُجمع في ملف واحد: `data/db.json` بجوار المشروع.

- ينشأ تلقائياً عند أول تشغيل، ولا يُرفع إلى git (يحتوي كلمات المرور).
- للنسخ الاحتياطي: انسخ هذا الملف واحفظه في مكان آمن.
- للمزامنة بين الأجهزة: شغّل `npm run dev` على جهاز واحد (السيرفر) وافتح رابط الشبكة من باقي الأجهزة.
- الواجهة البرمجية: `GET /api/store` لعرض البيانات، و`GET /api/store?meta=version` لمعرفة رقم الإصدار — وكلاهما **يتطلب تسجيل دخول** على السيرفر.
- بيانات الدخول: `POST /api/auth?action=login`، والخروج `POST /api/auth?action=logout`، والمستخدم الحالي `GET /api/auth?action=me`، وتغيير كلمة المرور `POST /api/auth?action=change-password`.

المنطق المشترك بين السيرفر المحلي والاستضافة موجود في `server/store.js` و`server/authApi.js`.

## 🔢 تحديد عدد الأرقام لكل مندوب

المدير يحدد بنفسه نصيب كل مندوب في كل دفعة، من مكانين:

- **الاستيراد من ملف (Excel / CSV / فيسبوك)**: ضع علامة على «تحديد عدد الأرقام لكل مندوب بنفسي» ← اكتب الرقم أمام كل مندوب (أزرار ±٥) أو اضغط «توزيع متساوٍ»، ثم استيراد. المتبقي لا يُوزّع.
- **السحب التلقائي من الكامبين**: حقل «عدد الأرقام لكل مندوب في الدفعة» في إعدادات السحب (٠ = بلا حد). مثال: 10 يعني كل مندوب يأخذ ١٠ أرقام كحد أقصى، والمتبقي يُسحب في الدفعة القادمة.

## 📥 استيراد الأرقام من فيسبوك / إنجاز

من تبويب **«توزيع الأرقام»** ← زر **«استيراد ملف أرقام»**:

1. نزّل الملف من فيسبوك (Ads Manager ← Leads Center ← تنزيل)، أو صدّر العملاء من إنجاز كـ Excel ثم احفظه CSV UTF-8.
2. ارفع الملف (أو اسحبه) — النظام يتعرّف تلقائياً على أعمدة الاسم والرقم والمصدر والحملة، حتى لو تغيّر ترتيبها.
3. راجع المعاينة: إجمالي الصفوف / أرقام جديدة / مكررة / غير صالحة، مع جدول يوضح كل صف قبل الإضافة.
4. اختر طريقة التوزيع: بالمناوبة على السيلز المختارين، أو كل الأرقام لشخص واحد.
5. اضغط «استيراد» — تظهر الأرقام فوراً في تبويب «أرقام جديدة» لكل سيلز وعلى كل الأجهزة.

**ما يفعله المستورد تلقائياً:**

- تنظيف الأرقام المصرية: `+201001234567` و `0020 111 222 3333` و `٠١٢٣٤٥٦٧٨٩٠` ← كلها تصبح `01xxxxxxxxx`
- حذف المكرر: مقابل الأرقام الموزعة سابقاً ومقابل كل عملاء النظام، وأيضاً المكرر داخل الملف نفسه
- تجاهل الصفوف بلا رقم صحيح، وتسمية من بلا اسم بـ «عميل بدون اسم»
- دعم ملفات CSV المُصدَّرة بترميز UTF-8 أو windows-1256 (ملفات إكسل العربية)

**للتجربة السريعة:** زر «نزّل ملفاً تجريبياً» داخل نافذة الاستيراد يعطيك ملفاً فيه ٩ أرقام بمشاكل مقصودة (مكرر، رقم ناقص، أرقام عربية) لتتأكد أن النتائج صحيحة قبل الاستخدام الفعلي.

> ملاحظة: صيغة xlsx غير مدعومة مباشرة — افتحها في إكسل ثم File ← Save As ← CSV UTF-8.

## 🔄 سحب الأرقام تلقائياً (بلا أي ضغطة زر)

من **«فريق العمل»** ← تبويب **«فيسبوك»** أو تبويب **«إنستجرام»**: النظام يقرأ الأرقام من المصدر من نفسه كل عدة دقائق، ينظّفها، يحذف المكرر، ويوزّعها بالمناوبة على السيلز — وتظهر لهم في تبويب «أرقام جديدة». (انتقل الإعداد من تبويب الإعدادات إلى هذين التبويبين.)

### 📘 📸 قناتان مستقلتان: فيسبوك وإنستجرام

كل قناة إعدادها كامل لوحدها: **التوكن** • **الصفحات** • **النماذج** • **كل كم دقيقة** • **مفتاح التشغيل/الإيقاف** • **مؤشر آخر سحب** • **نتيجة آخر عملية**. ولذلك:

- **إيقاف قناة لا يوقف الأخرى**، وانتهاء توكن فيسبوك لا يمنع سحب أرقام إنستجرام.
- **لا تختلط الأرقام**: كل رقم يدخل موسوماً بمصدره (`فيسبوك - اسم النموذج` أو `إنستجرام - اسم النموذج`) فيعرف الفريق من نظرة واحدة أي كامبين جاء منه.
- القناتان تُسحبان معاً في **دورة واحدة**، والمكرر يُرفض عبر القناتين (نفس الرقم لا يدخل مرتين حتى لو كان في الكامبينين).
- إعداد التوزيع (عدد الأرقام لكل مندوب) **مشترك** بين القناتين لأنه سياسة توزيع لا تخص كامبيناً بعينه.

> **لماذا إنستجرام في تبويب منفصل مع أنها نفس واجهة ميتا؟** ميتا تُنشئ نماذج إعلانات إنستجرام على **نفس صفحة فيسبوك** وتُقرأ بنفس التوكن والصلاحيات — لكن الفصل هنا يجعل لكل كامبين تبويبه ومؤشره واسمه، فتتبع أرقام إنستجرام وحدها وتوقفها وحدها بلا لمس أرقام فيسبوك.

**المصدر الأول (يعمل فوراً): رابط ملف منشور**

1. اجعل الأرقام في Google Sheet (أو أي ملف CSV عام).
2. Google Sheets: ملف ← مشاركة ← نشر على الويب ← اختر (قيم مفصولة بفواصل .csv) ← انسخ الرابط.
3. الصق الرابط في الإعدادات ← اضغط **تشغيل** ← ثم **جلب الأرقام الآن** لتتأكد أنه يقرأ بنجاح.

**المصدر الثاني: فيسبوك/إنستجرام مباشرة (توكن)**

1. أنشئ تطبيقاً من نوع **Business** على `developers.facebook.com` (مجاني).
2. من **Graph API Explorer** اختر تطبيقك، ثم فعّل هذه الصلاحيات **الخمس معاً**:
   `leads_retrieval + pages_manage_ads + pages_show_list + pages_read_engagement + pages_manage_metadata`
3. اضغط **Generate Access Token** ووافق على النافذة، ثم انسخ التوكن والصقه في الإعدادات.
4. عندك طريقتان:
   - **بالاستكشاف:** اضغط **«استكشف صفحاتي»** ← اختر صفحتك ← علّم **نماذج التسجيل (Instant Forms)** ← **حفظ الإعدادات** ← **تشغيل**.
   - **Form ID فقط (بدون استكشاف صفحات):** في قسم «أو أضف النموذج بمعرّفه فقط» الصق **Form ID** واضغط «أضف النموذج» ← **حفظ الإعدادات** ← **تشغيل**. السحب يتم مباشرة من `/{form-id}/leads` بالتوكن، فلا حاجة لاختيار صفحة.

> ⚠️ **أهم صلاحية:** بدون `pages_manage_ads` يرد فيسبوك بخطأ `#200 Requires pages_manage_ads permission` ويمنع قراءة النماذج والأرقام نهائياً — فلا تكفي `leads_retrieval` وحدها.
>
> التوكن من Graph API Explorer يعيش ساعتين تقريباً (جيد للتجربة). للاستخدام الدائم استخدم **System User Token** من Business Settings فلا ينتهي.

**بديل Form ID فقط:** لو معاك معرّف الفورم والتوكن، مش لازم تكتشف الصفحات أصلاً. أضف النموذج بمعرّفه (يظهر في Meta Business Suite داخل تفاصيل الفورم) وسيُسحب بالتوكن مباشرة. لو رفض فيسبوك الطلب بصلاحية، استخدم توكن صفحة أو أعد توليد التوكن بالصلاحيات الخمس.

**ملاحظات:**

- السحب يعمل ما دام **سيرفر التطوير يعمل** على جهاز الشركة (`npm run dev`).
- الإعدادات تُحفظ في `data/lead-source.json` (مستثنى من git، وفيه التوكن إن أضفته).
- كل عملية سحب تُسجّل نتيجتها وتظهر في نفس الكارت (كم رقم دخل، كم مكرر، وسبب الفشل إن حدث مثل انتهاء التوكن).
- الحد الأقصى ٢٠٠ رقم في المرة الواحدة، والتأخير الافتراضي ٥ دقائق (قابل للتعديل).

## 🚀 النشر على Vercel

ملف الإعداد جاهز: `vercel.json` (بناء `npm run build` ومجلد الإخراج `dist`)، ودالة البيانات جاهزة في `api/store.js`.

### ١) قاعدة البيانات المشتركة (أهم خطوة — بدونها كل جهاز لوحده)
ملفات Vercel **غير قابلة للكتابة**، فبدون قاعدة بيانات سيعمل كل جهاز لوحده ولا تظهر البيانات لباقي الفريق. الحل مجاني:

1. Vercel → مشروعك → **Storage** → **Create Database** → **Upstash Redis** → اختر الخطة **Free**.
2. اضغط **Connect** واختر المشروع — ستُضاف متغيرات البيئة تلقائياً.
3. أعد النشر (**Redeploy**) — بعدها `api/store.js` يقرأ ويكتب في السحابة.

بعد ذلك: أي حساب أو عميل أو رقم يسجّله أي جهاز يظهر على **كل** الأجهزة، ويبقى محفوظاً للأبد حتى لو مسح أحدهم بيانات متصفحه.

> الكود يتعرف تلقائياً على `KV_REST_API_URL/TOKEN` أو `UPSTASH_REDIS_REST_URL/TOKEN` — لا حاجة لتعديل أي شيء.
> الخطة المجانية تكفي فريقاً صغيراً، لكن **سقف قيمة واحدة ١٠ ميجا وسقف الطلب ٤ ميجا على Vercel**؛ وصور الوحدات تُخزَّن داخل قاعدة البيانات (base64)، فكثرة الصور الضخمة قد تصل للسقف. عندها إمّا نقلّل الصور أو ننقلها لتخزين منفصل.
> **الخصوصية:** `/api/store` **مغلقة تماماً** — لا تُقرأ ولا تُكتب إلا لمن سجّل دخوله فعلاً على السيرفر (انظر الخطوة ٤).

### ٢) رابط باسم شركتك (مثال: `emaargroupcrm.com`)

**أ) شراء الدومين** (مرة واحدة، ~١٠–١٢ دولار/سنة): من Namecheap أو Cloudflare Registrar أو GoDaddy — الأرخص عادةً Cloudflare (يبيع بسعر التكلفة بدون ربح).

**ب) ربطه بالموقع** — من لوحة Vercel:
1. مشروعك → **Settings** → **Domains** → اكتب `emaargroupcrm.com` → **Add**.
2. Vercel يعطيك سجلّي DNS: `A` بإسم `@` وبعنوان `76.76.21.21`، و`CNAME` بإسم `www` وبقيمة `cname.vercel-dns.com`.
3. افتح لوحة الدومين (مكان شرائه) → **DNS Records** → أضف السجلّين كما هما بالضبط.
4. انتظر من ١٠ دقائق إلى ساعتين — Vercel يشغّل **HTTPS** تلقائياً بمجرد ربط الـ DNS.

نجوم أخرى تريدها تلقائياً: مثل `www` أو `app.` أو `crm.` — نفس الخطوات بسجل `CNAME`.

### ٣) توزيع أرقام الكامبين تلقائياً ٢٤/٧ (بلا متصفح مفتوح)

Vercel المجاني يسمح بمهمة دورية واحدة يومياً فقط، فالحل المجاني هو خدمة جدولة خارجية:

1. أضف متغيّر بيئة على Vercel: `CRON_SECRET` = قيمة عشوائية طويلة (٣٢ حرفاً).
2. أعد النشر.
3. سجّل في [cron-job.org](https://cron-job.org) (مجاني) وأنشئ مهمة:
   - الرابط: `https://<رابط موقعك>/api/cron?key=<نفس قيمة CRON_SECRET>`
   - كل: **دقيقة** (أفضل قيمة — هي التي تجعل التذكيرات والإشعارات توصل في وقتها بالظبط؛ كل ٥ دقائق كانت تخلّي التذكير يتأخر لحد ٥ دقائق).

من هذه اللحظة الأرقام تُسحب من فيسبوك وتُنظَّف وتُوزَّع على السيلز **في السيرفر** وتُحفظ في القاعدة — حتى لو كل الأجهزة مقفولة. والمكرر لا يُضاف مرتين أبداً.
ونفس المهمة هي التي ترسل **إشعارات التذكيرات ورسائل الشات** (Web Push) لأجهزة الفريق والموقع مقفول — على آيفون وأندرويد.

> `api/cron.js` يفشل بأمان: بلا `CRON_SECRET` لا يعمل أصلاً (٥٠٣)، وبمفتاح غلط يرفض (٤٠٣).

> **الفاصل الزمني:** المجدول يمكن أن ينادي كل دقيقة (مهم للتذكيرات)، لكن سحب الأرقام يحترم إعداد «كل كم دقيقة» في تبويب القناة (افتراضي ٥ دقائق) ولا يسحب في كل نداء. زر «جلب الأرقام الآن» اليدوي يتخطى الانتظار.
>
> **بدون `CRON_SECRET`:** لا يوجد سحب ٢٤/٧ من السيرفر. كحل احتياطي، متصفح الإدارة يسحب تلقائياً كل الفاصل المضبوط ما دامت صفحة الإدارة مفتوحة. للعمل والأجهزة مقفولة لازم `CRON_SECRET` + مجدول خارجي.
>
> **حفظ كل رقم:** أي رقم جديد صالح يُحفظ في `crm_assigned_leads` حتى لو كل السيلز وصلوا حدهم الأقصى أو لا يوجد سيلز مفعّل؛ يُحفظ «غير موزّع» وتوزّعه الإدارة لاحقاً. لا يضيع رقم بسبب امتلاء الحصة.

### ٣-ب) سلوك التذكيرات والإشعارات (المتفق عليه مع الفريق)

| الحالة | ما يحدث بالظبط |
| --- | --- |
| حلّ وقت التذكير | بطاقة على شاشة الموقع + **إشعار في الجهاز** (صامت: بلا رنة وبلا تكرار)، والموقع مقفول الإشعار يفضل يوصل من السيرفر |
| كتبت كومنت بعد «تم الرد / لم يرد» في شاشة الاتصال | تظهر **قائمة الحالة المنسدلة** (follow up / done deal …) ثم **موعد الاتصال القادم**، والموعد يتسجّل تذكيراً في وقته |
| مافيش أي إجراء خلال ٥ دقائق (اتصال / تأجيل / تم) | التذكير يتسجّل **«متأخر»** ويتزاد عليه عدّاد التأخير — و«تأجيل» و«اتصال» يعتبران إجراءً فلا يُسجَّل تأخير |
| مكان وصول الإشعار | **أندرويد**: يعمل مباشرة أو بعد «إضافة إلى الشاشة الرئيسية». **آيفون**: لازم إضافة الموقع للشاشة الرئيسية (iOS 16.4 وأحدث) ثم ضغطة واحدة على «تفعيل الإشعارات» |
| تجدّد التسجيل | الجهاز يعيد تسجيل نفسه عند كل دخول تلقائياً، فلو تحدّث التطبيق أو تغيّرت قاعدة البيانات تفضل الإشعارات واصلة |
| منع ضياع الإشعار | التذكير لا يُعلَّم «تم إرساله» إلا بعد وصوله لجهاز واحد فعلاً — فلو فشل الإرسال أو ما كانش فيه جهاز مشترك يُعاد في الدورة القادمة |

> اختبارات هذا السلوك كلها آلية: `npm run test:push`.

### ٤) تأمين بيانات العملاء — **إلزامي** (دقيقة واحدة)
بيانات `/api/store` فيها أرقام عملاء حقيقية، وهي الآن **مغلقة على السيرفر**: لا تُقرأ ولا تُكتب إلا بكوكي جلسة صادر من `/api/auth` بعد تسجيل دخول صحيح. أي شخص يعرف رابط الموقع ويجرّب يفتح رابط البيانات مباشرة يحصل على **٤٠١ ولا يرى شيئاً**، وكلمات المرور لا تظهر في أي رد إلا لحساب الإدارة.

1. أضف متغيّر بيئة على Vercel: `AUTH_SECRET` = نص عشوائي طويل (٣٢ حرفاً على الأقل — استخدم مدير كلمات المرور أو موقع توليد عشوائي).
2. أعد النشر (**Redeploy**).

> **مهم:** بدون `AUTH_SECRET` يفشل كل شيء **بأمان** (٥٠٣) ولا تُفتح البيانات بالخطأ — فالموقع يظل مقفولاً حتى تضبطه.
> كل حساب يدخل بكلمة مروره المعتادة **بلا أي شاشة إلزامية**، ثم تُفتح له البيانات.
> على **سيرفر المكتب** (npm run dev) نفس الحماية تعمل تلقائياً: المفتاح يُولَّد مرة واحدة ويُحفظ في `data/.auth-secret` (خارج git) أو ضعه أنت في `.env`.

### ٥) تغيير كلمات المرور
- **من النظام (الطريقة المعتادة):** فريق العمل ← أي حساب ← زر التعديل — تظهر للـ CEO كلمة مرور الحساب وتستطيع تعيين واحدة جديدة من الحقل «تعيين كلمة مرور جديدة» (فارغة = الإبقاء على الحالية). السيرفر يقبل التغيير **من الإدارة وحدها** (`preserveUserPasswords`)، وأي محاولة من حساب آخر تُهمل تماماً.
- **من سطر الأوامر (بديل):**

```bash
node scripts/set-password.mjs --list                        # عرض كل الحسابات
node scripts/set-password.mjs --user admin                  # توليد كلمة مرور قوية وعرضها مرة واحدة
node scripts/set-password.mjs --user admin --password "..."  # تحديد كلمة المرور بنفسك
node scripts/set-password.mjs --user admin --local          # على ملف الجهاز المحلي بدل قاعدة الاستضافة
```

الأمر يعمل على قاعدة الاستضافة (Supabase/Redis) المسجّلة في `.env` من جهازك مباشرة، ويُسقط كل الجلسات القديمة للحساب بعد التغيير. (كلمة مُعيّنة منه تُحفظ مشفّرة فلا تُعرض في النظام — استخدم تغيير النظام إن أردت عرضها.)

### ٦) توكن فيسبوك دائم (System User Token)
التوكن من Graph API Explorer بينتهي بعد ساعتين — ده سبب رسالة «التوكن غير صالح». للحل الدائم:
1. `business.facebook.com` → **Settings** → **Users** → **System Users** → **Add** (نوعه Admin أو Employee).
2. اضغط **Generate New Token** → اختر تطبيقك → صلاحياته الخمس:
   `leads_retrieval + pages_manage_ads + pages_show_list + pages_read_engagement + pages_manage_metadata`
3. اختر التوكن **لا ينتهي** (Never expire) → انسخه.
4. الصقه في: التطبيق → **فريق العمل** → تبويب **«فيسبوك»** → «فيسبوك مباشرة (توكن)» → الصق → **استكشف صفحاتي** → علّم النماذج → **حفظ الإعدادات** → **تشغيل**. (ونفس الخطوات في تبويب **«إنستجرام»** لو عندك كامبين إنستجرام.)

التوكن يُحفظ الآن **على السيرفر** (قاعدة البيانات) فالسحب التلقائي يشتغل من نفسه بلا ما أحد يفتح الموقع.

أول مرة يسألك عن اسم المشروع ومجلد المشروع — اقبل الافتراضي (`dist` يُكتشف من `vercel.json`).

### ٧) أو الرفع من لوحة Vercel
1. ارفع المشروع إلى GitHub (المستودع خاص/Private مستحسن — لأن بيانات الدخول بيانات حقيقية).
2. Vercel → **Add New → Project** → اختر المستودع → سيُكتشف **Vite** تلقائياً → **Deploy**.

### ما يعمل على Vercel وما لا يعمل
| الميزة | على Vercel |
| --- | --- |
| كل النظام (عملاء، عقارات، مراحل، فيدباك، محادثات، حضور، تقارير) + المزامنة بين الأجهزة | ✅ يعمل عبر Redis |
| سحب أرقام الكامبين (فيسبوك + إنستجرام كقناتين مستقلتين) + التنظيف + التوزيع على السيلز | ✅ يعمل في السيرفر عبر `api/lead-source.js` |
| التوزيع التلقائي ٢٤/٧ بلا متصفح مفتوح | ✅ يعمل عبر `api/cron.js` مع مُشغّل مجاني (يكفي أن تكون قناة واحدة مفعّلة) |
| الرابط العام للعقار + الصفحات | ⚠️ يحتاج `api/public` (لم يُنقل بعد) |
| إشعارات الخلفية الحقيقية (Web Push والموقع مقفول) | ⚠️ تحتاج مُشغّلاً دورياً — تعمل حالياً على سيرفر المكتب |

بدون Redis: التطبيق يعمل طبيعياً لكن كل جهاز يحفظ بياناته وحده (الشارة تظهر «محلي»)، والسحب التلقائي يشتغل في المتصفح فقط وده يعدّي للوضع الاحتياطي («بلا ذاكرة»).

## 📄 ملفات الإعداد

| الملف | الوظيفة |
| --- | --- |
| `vercel.json` | إعداد النشر على Vercel (البناء، الإخراج، الترويسات) |
| `api/store.js` | دالة الاستضافة التي تخدم البيانات من Redis |
| `api/lead-source.js` | سحب أرقام الكامبين ودفعها للقاعدة (ووضع احتياطي بلا ذاكرة) |
| `api/cron.js` | المُشغّل الدوري المحمي الذي يوزّع الأرقام ٢٤/٧ |
| `server/store.js` | منطق التخزين المشترك (ملف JSON محلياً / Redis على الاستضافة) |
| `server/leadSource.js` | قلب التنظيف والتوزيع (يعمل محلياً وعلى الاستضافة بنفس الكود) |
| `tests/redis-smoke.mjs` | اختبار حقيقي بلا حساب: محاكي Redis يشغّل المزامنة والسحب والتوزيع |
| `tests/push-smoke.mjs` | اختبار الإشعارات: اشتراك مربوط بالجلسة + إرسال واحد لكل تذكير + تنظيف الاشتراكات المنتهية |
| `public/sw.js` | عامل الخدمة: يعرض إشعارات صامتة (نوتفكيشن فقط بلا رنة متكررة) ويفتح الموقع على التذكير |
| `.env.example` | أسماء متغيرات البيئة المطلوبة (لا تُرفع القيم الحقيقية) |
